Ek pointer consistently aage badhta hai — isko mover kehte hain. Doosra react karta hai window ki validity maintain karne ke liye — isko reactor kehte hain. Yeh distinction samajh aa jaaye toh koi bhi template yaad karne ki zarurat nahi — teen sawaalon se khud ban jaata hai. 1.1 Sliding Window vs Two Pointer — Fark Kya Hai? Pehle yeh decide karo ki problem two-pointer hai ya sliding window. Dono mein do pointers hote hain lekin movement bilkul alag hai. ▌ Sliding Window Dono pointers same direction mein chalte hain (left se right). Window = [tail..head] ek contiguous subarray/substring track karta hai. Koi bhi element window mein enter hota hai right se, exit karta hai left se. Sliding Window: tail ──────────────► head [ window ] tail aur head dono left se right Examples: LC 3, LC 76, LC 438, LC 30 ▌ Two Pointer Do pointers opposite ends se ya independent positions se kaam karte hain. Contiguous subarray track nahi hota — dono independently move karte hain logic ke hisaab se. Two Pointer (opposite ends): left ──► ◄── right [sorted array mein pair dhundh rahe] Two Pointer (fast/slow): slow ──► fast ──────────────► [linked list cycle, remove duplicates] Examples: LC 167 Two Sum II, LC 11 Container Water, LC 15 3Sum, Floyd cycle detection ▌ Ek Sawaal Se Decide Karo Signal Use Contiguous subarray/window track kar rahe ho Sliding Window Sorted array mein pair/triplet dhundh rahe ho Two Pointer (opposite ends) Linked list mein cycle/midpoint dhundh rahe ho Two Pointer (fast/slow) Window ka left/right boundary maintain karna hai Sliding Window Dono pointers independently move karte hain Two Pointer 1.2 Pattern Recognition — Keywords Se Template Identify Karo Problem statement padh ke yeh keywords dhundho. Template khud ban jaata hai. ▌ Sawaal 1 — Mover Kaun Hai? Mover outer loop drive karta hai. Woh consistently aage badhta hai. Tail = mover — jab har position ek valid start point hai (char-by-char problems) Head = mover — jab sirf kuch positions meaningful hain (chunked problems) Head mover ki pehchaan — teen signals: Elements chunked hain (words of same length, not individual chars) Duplicate elements possible hain → overuse → tail multiple steps react karta hai Invalid element pe full reset hota hai → tail bada jump karta hai ▌ Sawaal 2 — Reactor Kab React Karta Hai? Window valid hone pe react → EXPAND → CHECK → REACT Window invalid hone pe react → EXPAND → REACT → CHECK Fixed size → Scheduled → tail hamesha ek step, order matter nahi Valid pe react kyun check pehle hota hai: window valid hai abhi — record karo, phir tod do. Invalid pe react kyun react pehle hota hai: window toot gayi — pehle fix karo, phir record karo. ▌ Sawaal 3 — Reactor Kitna React Karta Hai? if — 1 step se window fix ho jaati hai (fixed size ya simple invalidity) while — unknown steps chahiye (variable size, overuse/duplicate case) Rule: fixed size window → hamesha if. Variable size window + invalid category → almost always while. 1.4 Master Template — Har Line Ki Wajah Yeh canonical template hai. Har line kyun likhi hai — explain karte hain. int tail = 0, head = -1; // LINE A while (tail &lt; n) { // LINE B while (expansion_condition) { // LINE C head++; // LINE D ds.add(s[head]); // LINE E } check_and_record(); // LINE F if (tail &lt; head) { // LINE G ds.remove(s[tail]); // LINE H tail++; // LINE I } else { // LINE J tail++; // LINE K head = tail - 1; // LINE L } } LINE A — tail=0, head=-1 kyun? head=-1 isliye kyunki pehla kaam inner while mein head++ hai. head++ se head=0 hoga — toh pehla element s[0] add hoga. Agar head=0 rakhte toh pehle element ko twice process karte ya phir head++ se skip karte. head=-1 ek clean starting state hai — &quot;abhi koi element window mein nahi hai.&quot; LINE B — while(tail &lt; n) kyun? Tail last valid position tak ja sakta hai. Jab tail = n-1, ek aur iteration possible hai. Jab tail = n, koi window nahi bach sakti — loop band. Note: kuch problems mein while(tail &lt;= n-k) likhte hain — kyunki agar tail itna aage ho ki k elements bhi nahi bach rahe toh koi valid window possible nahi. Yeh optimization hai, correctness ke liye zaruri nahi. LINE C — expansion condition kyun inner while mein? Inner while tab tak chalti hai jab tak head condition satisfy kare. Condition problem-specific hai: Fixed size: head - tail + 1 &lt; k → &quot;abhi k elements nahi hue&quot; Valid pe ruko: !seen.count(s[head+1]) → &quot;next char duplicate nahi hai&quot; Invalid pe ruko: formed &lt; required → &quot;window abhi valid nahi&quot; LINE D, E — head++ phir ds.add(s[head]) kyun yeh order? Yahi ADD symmetry hai. Pehle position advance karo, phir us position ka element DS mein daalo. Agar ulta karo — ds.add(s[head]) phir head++ — toh purana head ka element add hoga jo already window mein tha. Off-by-one bug. SAHI: head++; ds.add(s[head]); // naya element head pe add GALAT: ds.add(s[head]); head++; // purana element add, off by 1 LINE G — if(tail &lt; head) kyun check? Agar tail == head, window mein sirf ek element hai. Us element ko hatana matlab window empty ho jaayegi aur head &lt; tail ho jaayega — invalid state. Isliye else branch mein head ko reset karte hain. LINE H, I — ds.remove(s[tail]) phir tail++ kyun yeh order? Yahi REMOVE symmetry hai — ADD ka exact mirror. Pehle current tail ki value DS se hatao (jab tail abhi valid index hai), phir tail advance karo. Agar ulta karo — tail++ phir ds.remove(s[tail]) — wrong element hata doge. SAHI: ds.remove(s[tail]); tail++; // current tail hata, phir advance GALAT: tail++; ds.remove(s[tail]); // next position ka element hata — wrong LINE L — head = tail - 1 kyun? Jab window single element thi (tail==head) aur hum tail badha rahe hain, head ko bhi aage laana padega. Lekin hum head = tail nahi likhte — kyunki next iteration ki shuruat mein inner while ka pehla kaam head++ hai. Agar head = tail set karein toh head++ se head = tail+1 ho jaayega — ek element skip. Isliye head = tail-1 set karo taaki head++ ke baad head = tail ho. 1.5 Poora Template — Teeno Variants ▌ Variant A — Valid pe react (longest dhundh rahe) int tail = 0, head = -1; while (tail &lt; n) { while (head+1 &lt; Crux → Problem Connection Problem 1 · LC 76 — Minimum Window Substring [Hard] ▌ Problem Statement Do strings s aur t diye hain. s mein woh sabse chhota window dhundho jo t ke saare characters contain kare (correct frequency ke saath). Agar koi nahi toh empty string return karo. Input: s = &quot;ADOBECODEBANC&quot;, t = &quot;ABC&quot; Output: &quot;BANC&quot; ▌ Brute Force — O(n²) ya O(n³) Sabse simple approach: har possible window try karo aur check karo ki t ke saare chars hain ya nahi. // Brute Force O(n² * m) — TLE on large inputs for (int i = 0; i &lt; n; i++) { for (int j = i; j &lt; n; j++) { string window = s.substr(i, j-i+1); if (containsAll(window, t)) // O(m) check best = min(best, window); } } // Problem: har window ke liye fresh check // Prev window ka koi kaam nahi aata — sab waste Brute force kyun slow hai: jab i=0,j=5 se i=0,j=6 karte hain, toh sirf ek element badla. Lekin hum poori window dobara check karte hain. Yeh wasted work sliding window eliminate karta hai. ▌ Observation — Sliding Window Kyun? Key insight: window grow karne se woh valid hone ki taraf jaati hai. Ek baar valid ho gayi — shrink karo minimum dhundne ke liye. Har step mein sirf ek element add ya remove hota hai — DS incrementally update hoti hai, fresh check nahi chahiye. ▌ DS Identification need map — t mein har char ki required frequency have map — current window mein har char ki actual frequency formed — abhi kitne unique chars satisfy ho rahe hain (have[c] &gt;= need[c]) required — need.size() — total unique chars jo satisfy karne hain ▌ Teen Sawaal 1. Mover? tail — har position valid start candidate hai 2. React kab? Window valid hone pe (formed==required) → CHECK phir REACT 3. React kitna? while — valid window mein kai steps shrink ho sakti hai aur valid rahe ▌ Pseudocode while tail &lt; n: EXPAND: head++, have[s[head]]++ agar have[c] == need[c]: formed++ while formed == required: ← valid! check pehle CHECK: agar head-tail+1 &lt;
